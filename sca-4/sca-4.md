## Часть 4. Самостоятельная генерация SBOM
Иногда в проектах может встречаться собственный формат для описания зависимостей. В таком случае решением может быть самостоятельная генерация SBOM на основе данных, представленных в этом формате. В ходе части 4 мы научимся самостоятельно генерировать SBOM и проверять его валидность.

В ходе выполнения заданий 4 части у нас должны получиться следующие артефакты работы:
- скриншоты выполнения пунктов задания.
- файлы bom.json для обоих приложений.
- результаты анализа trivy/grype для обоих приложений

### Генерация SBOM
В ходе предыдущих частей мы уже посмотрели на то, как выглядит bom.json. Теперь попробуем самостоятельно сгенерировать его. Напишите 2 скрипта на Python, либо любом другом языке, которые на вход будут получать файлы с зависимостями конкретного проекта, а на выходе будут выдавать готовый для анализа bom.json.

1. Для проекта osquery, где зависимости описаны в файле https://github.com/osquery/osquery/blob/master/libraries/third_party_libraries_manifest.json
2. Для проекта envoy, где зависимости описаны в файле https://github.com/envoyproxy/envoy/blob/main/bazel/repository_locations.bzl

Проверить правильность сгенерированного bom.json можно с помощью `cyclonedx validate --input-file bom.json`.

Затем запустите на этих SBOM анализ с помощью trivy либо grype. Если все сделано правильно, то должны обнаружиться сработки.

### Итог 4 части
В ходе выполнения заданий 4 части мы научились самостоятельно генерировать SBOM, проверять его валидность и теперь готовы к любым задачам, связанным с изменением SBOM.
