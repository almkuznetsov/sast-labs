## Часть 1. Golang SCA, CycloneDX, SBOM, Trivy
С помощью статического анализа можно находить новые ошибки в коде нашего проекта. Однако часто мы используем большое количество разных опенсорс-зависимостей, в которых уже есть известные уязвимости, которые могут влиять и на наш проект. Для того, чтобы знать состав нашего приложения и следить за уязвимостями в его зависимостях применяются техники композиционного анализа (Software Composition Analysis, SCA).

Выполнение этой работы подразумевает выполнение sast-7, поэтому здесь не описывается способ создания репозиториев в SourceCraft и работа с платформой.

В ходе выполнения заданий 1 части у нас должны получиться следующие артефакты работы:
- скриншоты выполнения пунктов задания.
- файлы bom.json для обоих приложений.
- публичные форки репозиториев в SourceCraft с размеченными сработками SCA.

### Анализ damn-vulnerable-golang
У проекта damn-vulnerable-golang из задания sast-7 нет зависимостей, в этом можно убедиться, открыв его go.mod-файл. Давайте добавим в его `main.go` использование bcrypt и зависимость на уязвимую версию golang/x/crypto:

`main.go`:
```Go
import (
	<...>

	"golang.org/x/crypto/bcrypt"
)

Hash, _ := bcrypt.GenerateFromPassword([]byte(password), bcrypt.MinCost)
```

`go.mod`:
```Go
require golang.org/x/crypto v0.0.0-20190701094942-4def268fd1a4
```

После выполнения `go mod tidy` убедимся, что `go.sum` тоже обновился актуальными данными о зависимостях.

Для анализа зависимостей нам потребуется их список не в формате `go.mod`, а в принятом формате для композиционного анализа, например CycloneDX.
```shell
apt-get install cyclonedx-gomod
cyclonedx-gomod mod -json -output bom.json
```
В результате мы получили файл `bom.json`, содержащий информацию о всех завсимостях нашего проекта. Это пример SBOM - Software Bill Of Materials. Его в свою очередь можно передавать в различные сканеры для поиска уязвимых компонентов. Попробуем передать наш SBOM для анализа в опенсорс-сканер trivy.

```shell
apt-get install trivy
trivy sbom bom.json
```
Если все сделано правильно, то мы увидим несколько уязвимостей, относящихся к нашей версии crypto. Посмотрим на результаты и оценим их применимость к нашему коду.

Загрузите новый код в SourceCraft и убедитесь, что во вкладке Dependencies получаем те же результаты запуска trivy, что и были у нас локально.

### Анализ geoipupdate
Аналогичным образом соберите SBOM для проекта geoipupdate версии 7.0.0 из sast-7. Проанализируйте его с помощью Trivy. Сравните результаты с результатами во вкладке Dependencies в SourceCraft. Если они не совпадают, определите почему и добейтесь совпадения. Разберите две любые **разные** сработки в SourceCraft.
