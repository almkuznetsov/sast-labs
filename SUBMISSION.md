# Формат сдачи SAST-1–4

Результат каждой части сдаётся одним PR в выданный репозиторий. Все проверяемые материалы должны находиться в ветке PR, а не только в его комментариях или внешних сервисах.

После открытия PR добавьте `@almkuznetsov` в reviewers.

## Структура результата

```text
submission/
├── submission.json
└── artifacts/
    ├── screenshots/
    │   └── ...
    └── ...
```

Точные имена файлов в `artifacts` указаны в соответствующей части работы. Скриншоты, добавленные только в описание или комментарии PR, не считаются сданными артефактами.

Рекомендуется сделать два коммита: сначала коммит с исправлением исходного кода, затем коммит только с `submission/**`. Файл `fix.patch` должен быть создан из первого из этих коммитов.

## submission.json

```json
{
  "schema_version": 1,
  "assignment": "sast-1",
  "base_commit": "полный SHA базового коммита PR",
  "fix_commit": "полный SHA коммита с исправлением",
  "environment": {
    "os": {
      "id": "значение ID из /etc/os-release",
      "version_id": "значение VERSION_ID из /etc/os-release"
    },
    "analyzer": "имя анализатора",
    "analyzer_version": "точная версия анализатора"
  },
  "analysis": {
    "before": {
      "command": "точная команда запуска",
      "artifact": "submission/artifacts/имя файла или каталога"
    },
    "after": {
      "command": "точная команда запуска",
      "artifact": "submission/artifacts/имя файла или каталога"
    }
  },
  "target_finding": {
    "detector": "идентификатор детектора",
    "path": "путь к исходному файлу",
    "function": "имя функции с ошибкой"
  },
  "patch": "submission/artifacts/fix.patch"
}
```

В `environment.os` укажите `ID` и `VERSION_ID` из вывода `cat /etc/os-release` в среде, где запускался анализатор: на ВМ, физической машине или внутри контейнера. Оба значения записываются строками без внешних кавычек из `os-release`; прикладывать весь вывод не требуется. При использовании контейнера можно дополнительно указать необязательное поле `environment.container` с именем и версией образа, например `"container": "registry.altlinux.org/alt/alt:p11"`.

SHA коммитов указываются полностью в полях `base_commit` и `fix_commit`. Результаты `analysis.before` относятся к `base_commit`, а `analysis.after` — к `fix_commit`.

Команды приводятся без сокращений и должны запускаться из корня репозитория.

## Предметные скриншоты

В каждой части указаны этапы, на которых нужно сделать скриншоты. Они сохраняются под указанными именами в `submission/artifacts/screenshots/`.

Все скриншоты сдаются как исходные PNG размером не менее 1000×600, без редактирования после съёмки.

## Что проверяется

- `base_commit` совпадает с базовым коммитом PR;
- `fix_commit` входит в историю PR;
- `fix.patch` применяется к `base_commit` и соответствует исправляющему коммиту;
- артефакты до и после исправления относятся к заявленным коммитам;
- целевое срабатывание устранено без отключения детектора или исключения файла из анализа;
- PoC воспроизводит ошибку до исправления и не вызывает прежнего аварийного завершения после него;
